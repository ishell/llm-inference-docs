# GLM-5.2 24×B300：SLA 不是峰值吞吐，TPOT 40ms→17ms

英文对照：`en/vllm/blog/serving/glm52-b300.md`  
原文：https://vllm.ai/blog/2026-07-23-glm-5.2-nvfp4-b300-pd  
3×8 B300，4P1D。GLM-5.2-NVFP4（744B / 40B active）。mean TTFT ≤2.5s，mean TPOT ≤20ms。图在原网页。

P/D 是起点：colocated 里长 prompt 会把正在 decode 的 ITL 拉长，TPOT SLA 没法签。最大的一刀不是 kernel——P/D 交接后第一 decode step 只有 1 token，MTP 已在跑的请求是 1+N，混合 batch 掉出 full CUDA Graph。DP 下任一 rank 接新请求，全 ranks 跟下去。dummy speculative padding（PR #45237）把形状垫齐：**~40ms → ~22ms**。

再往下：MoE 要显式 `VLLM_USE_V2_MODEL_RUNNER=1`，MRV2 再砍 TPOT 约 **11%**（DSA indexer warmup、MTP local argmax、动态 speculative + full graph）。FlashInfer NVLink A2A `flashinfer_nvlink_two_sided` 再约 **4%**。Decode `--compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}'`。MTP decode `num_speculative_tokens=3`，prefill 只 1。IndexerCache 让 DSA 的 Top-K 在 MTP 迭代间共享，否则 indexer 每步重跑，投机不划算。

Prefill：TP1 DP2 EP 的 TGS 最好，他们仍发 **TP1 DP4 EP**——少约 8% per-GPU，换四卡 KV，保住 1M 上下文。吞吐最高的配置不一定能签 SLA。PCP virtual batching 以后可能改这笔账。监控把 MTP acceptance 当一等告警；长稳测发现 `new_block_ids` 对非 Mamba 模型只记不清，host RSS 线性涨（#47723 / #44490）。v0.26.0 已收齐他们踩过的坑。
