# 中文体例

中文笔记的口吻对齐 [《Crafting Interpreters》中文译本](https://github.com/ishell/crafting-interpreters-zh-cn) 的 `book/`：完整书面语、带一点温度，但是**翻译**，不是另写一篇散文。英文对照页（`en/`）不改这套口吻。

仍不是官方译本。原页版权归原站。指标名、CLI、类名、公式保留英文。`voice:` 用 `book-zh`。

## 人称

和那份译本的 `note/style guide.md` 一样：

1. 跟着代码或请求走一遍时，用**我们**：「我们调用 `generate`」「我们把这条请求放进 `waiting` 队列」。
2. 读者要动手改配置、跑命令时，也用**我们**（不要用「请你去拧」）。
3. 讲一段机制本身怎么工作时，可以用**它**：「调度器决定下一步谁上场」。

少用第二人称训话。可以对读者说「你」，但只在真正面向读者的时候（「如果你是第一次读这篇」），不要整篇用「你」把系统拟人成客人。

## 不要另造比喻

原文有比喻，我们译比喻。原文没有，就不要加「屋子塌了」「门厅不够站」「钝刀」「侍候 LLM」「把旋钮拧到头」「厨师等端菜」「烤蛋糕」这类学习笔记修辞。

可以保留工程里已经约定的说法：排队、抢占、吞吐、延迟、基线。不要把 TTFT 写成「等待第一个字的人」。

## 术语

- **TTFT、ITL、TPOT、TPS、RPS、Prefill、Decode、KV cache** 以及 CLI 旗标、类名、环境变量：一律英文。首次出现可以在中文说明后面括注英文，但不要把 TTFT 译成「首字延迟」当标题。
- 可以中文化的普通词：吞吐、延迟、调度、量化、张量并行。首次定义时**加粗**。
- 类名不用代码字体：「`EngineCore`」在行文里写成 EngineCore，或第一次写 **EngineCore**。旗标、语句、字面量用反引号：`--max-num-seqs`、`true`。
- 文件名加引号：「optimization.md」。

## 标点与代码

- 段末若是完整句子，用句号。下一段代码若被这句话直接点名，可以用冒号。不要每个段都用冒号吊着代码块。
- 列表里若开头是独立术语，术语加粗，后面用破折号接说明。
- 数字在叙述里能写成汉字的（一、十一）可以写成汉字；指二进制位、版本号、吞吐数字保持阿拉伯数字。

## 改写时保留什么

结构、数字、代码块、表格、caveat、链接、本地图路径都保留。只改句子怎么说。不要为了「好读」删掉 API 或附录命令。

## 对照

| 旧（学习笔记修辞） | 新（译本口吻） |
|---|---|
| 屋子里突然挤进一百个人，门会不会塌 | 压测（load testing）模拟真实流量，看系统在高并发下的容量、伸缩、网络和资源 |
| 有人在等第一个字 | TTFT 从提交请求到收到第一个非空 token |
| Engine 还不能把窗口开给互联网上那个正在等第一个字的人 | 引擎自己已经能做高吞吐推理，但只适合离线场景，还不能通过网络对外提供服务 |
| 先确认这座房子里的 CPU 核够不够 | 官方建议先确认 CPU 核数量是否足够（V1 是多进程） |
| 侍候 Llama | 在 … 上部署 / 运行 Llama |
